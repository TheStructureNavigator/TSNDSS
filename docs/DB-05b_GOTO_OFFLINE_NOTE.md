# DB-05b — GoTo with native ScopeGoto events (offline). Physical GoTo is BLOCKED.

Status: **IMPLEMENTED (offline) only. No hardware verification. Physical execution is disabled** by `seestar_control.commands.GOTO_PHYSICAL_ENABLED = False`: the provider refuses before any frame is sent and the CLI refuses `--command goto` before building anything. Tests switch the flag on only against simulators and fake sockets.

## What it does

1. **Protocol (third-party reference, never run on firmware 9.31).** `scope_goto` takes positional `[RA_hours, Dec_degrees]`. The end of the slew is announced as an unsolicited `ScopeGoto` event *on the connection that issued the request*; the reference reads `Event`/`event`, a string `state` (`working`/`start` = progress; `complete`/`fail`/`cancel` = end), and counts an end only on an *outer* frame (no `page` key, and `route` or `lapse_ms` present). The firmware is said to drop an idle connection after about 15 s, hence a keepalive. Primary sources: seestarpy `ui.py` and `connection.py`; seestar_alp `device/*.py` (read as protocol references only, no code copied).
2. **Transport.** `SeestarControlTransport.open_goto(host, target)` does the existing authenticated handshake, sends `scope_goto`, reads the reply (keeping any frames that arrive behind it) and **keeps the socket open** in a `GotoWatch` (`goto_watch.py`). The watch is one object per GoTo, not a bus: `pump()` reads what is there (bounded), sends the allow-listed read `test_connection` every `GOTO_KEEPALIVE_S` (5 s, a protocol parameter taken from the reference, owner-visible, `None` disables), and recognises only the strict envelope above. Non-JSON, other events, wrong types, unknown states and inner terminal frames are ignored (an inner terminal is only recorded as provisional and never ends the watch). A closed or failing connection or an oversized frame ends it as `lost`; nothing is inferred from a loss.
3. **Command path.** `GotoTarget` (validated RA hours / Dec degrees), the `parameters` plumbing, the `seestar.mount.goto` kind, the `OperatorPermit` + single-use `ARM` confirmation, the DB-04 gates, uncertainty handling and "no blind retry" are unchanged from the first increment. The provider keeps the watch per command id; `poll_command` reports `IN_PROGRESS` once progress was seen, `REPORTED_COMPLETE` only for an outer `complete`, `REPORTED_FAILED` (effect possible, so `unknown_result` by amendment A1) for `fail`/`cancel`, and raises on a lost connection (also `unknown_result`). The provider closes any open GoTo connection on disconnect. No deploy, park, camera or tracking command is ever issued.
4. **Verification.** `VERIFIED` = an outer `ScopeGoto complete` seen after the submission boundary **and** a fresh post-submission sample with the mount stationary. The evidence text says "firmware-reported ... target centering is NOT confirmed". `scope_get_equ_coord` is an optional cross-check (when `goto_tolerance_deg` is configured): a fresh disagreeing reading is contradictory evidence and keeps the verdict `PENDING` (then `unknown_result` at the deadline); an unreadable one is reported as "not cross-checked". `fail`, `cancel`, `lost`, a missing event or any doubt never verify.
5. **Pointing safety (owner-configurable, no defaults).** `GotoSafety(site, min_altitude_deg, min_sun_separation_deg, ephemeris)` and a `parameter_gate` on the policy, evaluated by the executor's gate at admission and again at submission (so it cannot be bypassed through the executor). It needs a valid Site latitude/longitude, a timezone-aware time and a working ephemeris; anything it cannot evaluate blocks (`pointing_evaluation_failed`; no configured policy: `pointing_policy_not_configured`; otherwise `target_below_minimum_altitude` / `target_too_close_to_sun`). The sky geometry (`tsn_dss/engine/pointing_geometry.py`, astropy, lazily imported, using the Site model's latitude/longitude/elevation) is injected, which keeps `seestar_control` stdlib-only. These are TSN DSS policy proposals, **not device limits**: no device-supported movement limit is known.
6. **Coordinates.** Provisional convention: targets are *of-date* (FK5 at the equinox of the time, "JNow"), because seestar_alp treats device coordinates that way; **the firmware's frame is not verified**. `--frame of-date|j2000` is mandatory (an unstated frame is refused); `j2000` is converted explicitly by `pointing_geometry.j2000_to_of_date` and the report shows both the input and the converted values.

## Owner decisions still needed before the first physical test

1. **Limits.** Values for `--min-altitude-deg` and `--min-sun-separation-deg` (none are suggested or defaulted here), whether a solar filter may ever be assumed, and the Site used for the check (its latitude/longitude/elevation must be right and should be compared with the device's own configured location, which DB-02 deliberately does not read).
2. **Coordinate frame.** Accept the provisional of-date convention for a first supervised test, or require the read-only watch experiment first (official-app goto to a catalog object while polling `scope_get_equ_coord`).
3. **Contract.** DSS-CTR-013 section 10 says movement operations "shall be deferred until movement-specific safety policy is defined". The pointing gate is a first such policy; the owner decides whether it suffices or whether an amendment/record is required. The optional `parameters` on a Command request was treated as additive and compatible.
4. **Timing.** Deadline (it must exceed the longest slew), poll interval (it must be well below the idle-connection limit, otherwise the keepalive cannot run and the watch may be lost), and `GOTO_KEEPALIVE_S`.
5. **Cancellation/abort.** Still refused. The reference cancels with `iscope_stop_view` stage `ScopeGoto`/`AutoGoto`; not wired.
6. **Roadmap placement.** Recommended: a separate DB-05b milestone after DB-05 failure/recovery hardware validation.

## Unknown until hardware

The real envelope of the ScopeGoto event on firmware 9.31 (an end that arrives only as an inner frame would never verify and would end in `unknown_result`); whether events also reach a connection that did not issue the command; the reply to `scope_goto`; the firmware's refusal behaviour below the horizon; the frame; tracking afterwards; behaviour with scenery running.

## To enable

Resolve the decisions, run read-only hardware captures for them, then change `GOTO_PHYSICAL_ENABLED` in a reviewed commit and validate step by step: one supervised GoTo with the step prompts, then the failure and recovery paths.
